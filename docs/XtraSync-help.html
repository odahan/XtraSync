Guide utilisateur · Français

Comparer, comprendre,
synchroniser.

Tout ce qu’il faut savoir pour comparer deux dossiers, créer un miroir ou synchroniser dans les deux sens avec XtraSync.

L’interface de l’application est en anglais. Les noms de boutons sont donc conservés tels qu’ils apparaissent à l’écran. Cette aide fonctionne hors connexion. Utilisez le sommaire, Ctrl + F pour rechercher et Ctrl + P pour imprimer la langue affichée.

Un miroir peut supprimer des données. Vérifiez le sens de l’opération et le récapitulatif avant de valider. Les suppressions sont définitives, hors Corbeille, et les versions remplacées ne sont pas archivées par XtraSync. Une opération interrompue ne restaure pas les changements déjà terminés.

01 · Premiers pas

  1. Lancez XtraSync.exe depuis un emplacement où vous pouvez écrire : l’application y place ses logs, ses rapports et son aide.
  2. Renseignez LEFT FOLDER (dossier gauche) et RIGHT FOLDER (dossier droit) par saisie, avec Browse… ou en faisant glisser un dossier depuis l’Explorateur Windows sur le champ voulu. Les deux dossiers doivent exister, être accessibles et être distincts. Les dossiers imbriqués sont refusés.
  3. Choisissez les critères de comparaison et les exclusions. Par défaut, les sous-dossiers, les tailles et les dates sont pris en compte, avec une tolérance de deux secondes.
  4. Commencez avec Compare folders pour voir les différences. Cette comparaison ne modifie pas les données des dossiers ; elle crée toutefois le log de l’opération et, si demandé, un rapport.
  5. Choisissez ensuite un miroir ou une synchronisation bidirectionnelle. Examinez la liste exacte des actions, leurs nombres et leurs tailles, puis validez avec Apply mirror ou Apply synchronization.
  6. Lisez le résultat final. En cas de problèmes ou d’avertissements, consultez XtraSync.log, dont le chemin apparaît en bas de la fenêtre.

Déposez un seul dossier à la fois. Son chemin complet remplit le champ et rejoint l’historique de ce côté. Les fichiers et les sélections multiples sont ignorés. Les listes déroulantes conservent séparément les dix derniers chemins de gauche et de droite, sans doublons. Le choix d’un chemin dans l’historique ne lance aucune opération.

02 · Choisir un mode

Effets des quatre commandes principales
CommandeComportement
Compare foldersBalaye les deux côtés et affiche leurs différences, sans copier ni supprimer de données.
Mirror to right →La gauche est la source, la droite est la cible. Copie les éléments manquants ou différents de gauche vers la droite ; supprime de la droite les éléments absents de la source, dans le périmètre retenu.
← Mirror to leftLa droite est la source, la gauche est la cible. Les mêmes règles s’appliquent en sens inverse.
Synchronize Both WayCopie les éléments présents d’un seul côté vers l’autre, et remplace une version plus ancienne par la version plus récente lorsque les règles permettent de la départager. Aucune suppression n’est propagée.

En miroir, la source fait autorité. Pour deux fichiers au même chemin relatif et dans le périmètre du miroir, une différence de date détectée par Compare timestamps après application de la tolérance et de l’option horaire, ou une différence de taille détectée par Compare sizes, suffit pour prévoir le remplacement. Une source plus ancienne peut donc écraser une cible plus récente. Lorsque les critères activés donnent Equal, le fichier cible est conservé.

Un fichier source absent de la cible est prévu en copie. Un conflit fichier/dossier peut entraîner la suppression de l’élément cible et sa recréation sous le type de la source. Ces actions figurent dans l’aperçu.

En bidirectionnel, une suppression n’est pas mémorisée : si vous effacez un fichier d’un côté mais qu’il existe encore de l’autre, il sera recopié. Les conflits fichier/dossier et les différences sans version plus récente identifiable sont laissés inchangés et signalés dans l’aperçu. Résolvez-les manuellement puis relancez une opération.

03 · Règles de comparaison

XtraSync compare les métadonnées des fichiers : taille et date de modification. Il ne calcule pas d’empreinte et ne compare pas leur contenu octet par octet. Deux fichiers de même taille et de même date peuvent donc être indiqués égaux alors que leur contenu diffère.

OptionEffet
Subfolders includedCochée par défaut. Inclut les sous-dossiers et leur contenu. Décochée, limite le travail aux fichiers directement dans les racines : les sous-dossiers et leur contenu ne sont ni copiés ni supprimés.
Compare sizesCochée par défaut. Une différence de taille signale une différence lorsque les dates ne désignent pas déjà une version plus récente.
Compare timestampsCochée par défaut. Permet de distinguer la version la plus récente et de guider les copies bidirectionnelles.
Tolerance (seconds)Entier positif ou nul, initialement 2. Un écart de dates inférieur ou égal à cette tolérance est considéré équivalent. Les dates sont comparées à la seconde.
Ignore whole-hour time zone differencesDécochée par défaut. Considère équivalents les écarts proches d’un nombre entier d’heures, dans la tolérance choisie, pour des écarts inférieurs à 24 heures. À utiliser uniquement si le décalage horaire explique réellement ces différences.

Si les deux critères sont décochés, deux fichiers présents au même chemin sont considérés égaux, quel que soit leur contenu. Si les dates sont désactivées ou équivalentes et que les tailles diffèrent, le mode bidirectionnel ne choisit pas arbitrairement une version : il signale un conflit.

Lire le tableau des résultats

Le compteur differences donne le nombre de lignes du tableau, pour une comparaison directe comme après un miroir ou une synchronisation. Equal désigne des fichiers jugés équivalents par les critères activés. Ces fichiers et les dossiers présents des deux côtés entrent dans les totaux de comparaison. Un tableau vide après une comparaison terminée correspond à zéro différence dans le périmètre analysé.

Les chemins sont relatifs aux racines sélectionnées et les dates affichées utilisent l’heure locale. Left only / Right only indique une entrée présente d’un seul côté, Left newer / Right newer une version plus récente à gauche / à droite, Different size une taille différente, Type conflict un fichier d’un côté et un dossier de l’autre, et Unavailable un accès insuffisant pour conclure. Les entrées Unavailable figurent dans le tableau et dans le compteur differences.

04 · Exclusions et filtres

Le filtrage agit en amont, pendant le balayage. Les fichiers exclus ne sont pas ouverts pour lire leur contenu ni comparés ; les dossiers exclus ne sont pas parcourus. Leurs noms et, lorsque nécessaire, leur type sont néanmoins examinés pour appliquer le filtre.

Saisie sur l’écran principal

La zone Exclusions est une liste déroulante éditable. Séparez les motifs par un point-virgule :

*.tmp; .git; file:*.bak; folder:bin; folder:obj; file:cache/*.log
  • Sans préfixe, le motif vise les fichiers et les dossiers.
  • file: limite le motif aux fichiers ; folder: aux dossiers.
  • La ligne courante est sauvegardée automatiquement, même saisie manuellement ou vidée. Les dix dernières lignes complètes non vides sont conservées sans doublons. Validez avec Entrée ou quittez la zone pour mémoriser une ligne ; une ligne réutilisée revient en tête.

Dialogue Filters…

Le bouton à icône de filtre ouvre Name filters. À l’ouverture, la ligne principale est décomposée dans Exclude files and folders, Exclude files et Exclude folders. Entrez un motif par ligne, sans point-virgule, et sans ajouter les préfixes file: / folder: dans les champs spécialisés.

Save filters reconstruit et sauvegarde la ligne principale avec ses séparateurs et préfixes. Cancel abandonne les modifications du dialogue. Clear filters vide le brouillon ; cliquez ensuite sur Save filters pour appliquer ce changement.

Syntaxe des motifs

MotifCorrespondance
*.tmpNoms terminant par .tmp, à n’importe quelle profondeur.
photo?.jpgUn seul caractère à la place de ?, par exemple photo1.jpg.
folder:cacheTout dossier nommé cache, et tout son contenu.
file:cache/*.logFichiers .log directement dans cache à la racine ; ne vise pas other/cache/a.log ni cache/sub/a.log.

* représente zéro ou plusieurs caractères et ? un caractère, sans traverser un séparateur de dossier. Un motif sans séparateur vise un nom à toute profondeur ; avec / ou \, il vise un chemin relatif à la racine. La casse est ignorée. Les espaces en début et fin sont retirés ; les espaces internes et les virgules sont littéraux. Il n’y a ni syntaxe d’inclusion, ni exception avec !, ni signification récursive spéciale de **. Le point-virgule est réservé à la séparation des motifs.

Que devient l’élément correspondant dans la cible ?

En miroir : les éléments exclus sont absents de la source logique. Par défaut, les éléments cibles correspondant aux exclusions sont préservés ; les dossiers qui les contiennent sont protégés contre une suppression ou un remplacement destructeur.

L’option principale Delete excluded items from mirror destination, décochée initialement, autorise leur suppression dans la cible du miroir. Les suppressions sont incluses dans le récapitulatif à valider. Le sens s’inverse avec le miroir choisi. Pour préparer ces suppressions, la cible doit être inspectée, y compris ses éléments exclus ; la source reste filtrée en amont.

En bidirectionnel : les exclusions sont simplement ignorées des deux côtés, sans copie ni suppression. L’option de suppression des exclus n’y est jamais appliquée, même si elle reste cochée ; un avertissement est alors journalisé.

05 · Valider les modifications

Chaque miroir ou synchronisation prépare un plan avant de modifier les fichiers. Le dialogue de validation indique les racines, le sens, la liste des actions, les dossiers à créer/supprimer et les conflits laissés inchangés.

  • Files to copy (including replacements) : nombre de fichiers à copier et taille de leurs nouvelles versions, remplacements compris.
  • Files to delete : nombre et taille des fichiers à supprimer explicitement.
  • Existing versions to overwrite (included above) : nombre et taille des anciennes versions à écraser. Les fichiers concernés sont déjà inclus dans le groupe des copies ; n’additionnez pas ces groupes comme s’il s’agissait de fichiers distincts.

Les totaux représentent des opérations : un changement de type peut produire plusieurs actions sur le même chemin. La taille des fichiers ne prédit pas exactement l’espace libre nécessaire ; la préparation d’une copie utilise un fichier temporaire dans le dossier cible.

Apply mirror ou Apply synchronization autorise le plan affiché. Annuler ou fermer le dialogue ne modifie pas les données. S’il n’y a aucune action, rien n’est exécuté. Avant exécution, le plan est revérifié ; une modification imprévue peut imposer un nouveau balayage et une nouvelle validation.

Les tableaux de résultats et de Review changes utilisent les mêmes barres de défilement sombres, verticales et horizontales.

06 · Suivi et commandes

La zone inférieure suit toutes les phases : balayage, comparaison, préparation, validation et exécution. Pendant le balayage, le nombre total n’est pas encore connu ; la barre peut donc être indéterminée. Le pourcentage d’exécution porte sur les actions traitées, pas sur le temps restant.

  • Copy / Delete : fichiers et tailles effectivement terminés par rapport aux valeurs prévues ; les remplacements font partie des copies.
  • Folders : dossiers créés et supprimés, réalisés / prévus.
  • Transferred : octets transférés, y compris les tentatives partielles ou répétées ; ce total peut dépasser la taille prévue ou les octets validés.
  • Current file : chemin courant et progression dans le fichier pendant la copie.
  • Problems : fichiers/dossiers en échec, opérations dépendantes ignorées, éléments déjà absents, accès indisponibles, nouvelles tentatives et nombre de fichiers distincts ayant subi une erreur de lecture.

Les tailles sont formatées en unités de 1 024 octets.

Comparaison finale et activité du disque

Compare folders after mirroring s’applique aux deux sens du miroir. La case est décochée par défaut et son état est mémorisé entre les sessions. Décochée, elle laisse le tableau vide et le bilan indique Final comparison skipped. Vous pouvez alors lancer Compare folders à la demande. La synchronisation bidirectionnelle actualise automatiquement le tableau après exécution.

Si la comparaison finale est activée, Scanning folders peut s’afficher alors que les compteurs de copies et de suppressions ont atteint leurs totaux. XtraSync reparcourt les deux dossiers en lecture seule, affiche les chemins rencontrés et lit leurs métadonnées. Le volume scanned cumule les tailles des fichiers recensés. Transferred reste le volume des copies effectuées pendant l’exécution. La phase Comparing entries utilise ensuite les métadonnées pour remplir le tableau des écarts, puis le bilan du miroir s’affiche.

Cette comparaison peut révéler un changement survenu pendant ou après le miroir, par exemple une modification par un autre programme. Une comparaison ignorée laisse ces écarts éventuels à vérifier manuellement. La validation du plan, les vérifications de copie, le bilan et le log font partie de l’exécution dans les deux cas. Le contrôle final repose sur les tailles et les dates sélectionnées.

Travail en arrière-plan et parallélisme

Le calcul s’exécute en arrière-plan pour que l’interface reste disponible. XtraSync parcourt les deux dossiers successivement, compare les entrées en mémoire une par une et applique les actions du miroir dans l’ordre du plan. Les copies sont exécutées une à la fois, y compris en synchronisation bidirectionnelle.

Un parcours en parallèle pourrait aider sur deux supports distincts et ralentir un disque dur partagé. Une éventuelle mise en parallèle de la comparaison en mémoire, par exemple avec PLINQ, doit préserver l’ordre des résultats et agréger les compteurs. Pour les miroirs, seules les actions indépendantes peuvent se chevaucher. Une limite de tâches simultanées borne la concurrence. Une limite de débit est une mesure distincte, car une seule copie peut déjà saturer un disque lent.

CommandeEffet
Pause / ResumeSuspend/reprend au prochain point de contrôle, y compris entre blocs de copie. Un appel Windows déjà bloqué peut retarder la prise en compte.
StopDemande un arrêt propre, nettoie les temporaires lorsque possible et termine le log et le rapport demandé. Les actions déjà terminées sont conservées.
RestartArrête et attend l’opération active si nécessaire, puis relance le même mode avec un balayage et un plan neufs. Les modifications exigent une nouvelle validation. Un nouveau log est créé.
Fermer la fenêtreDemande l’arrêt et attend la finalisation avant de quitter. Ne forcez pas la fermeture du processus si vous souhaitez laisser cette finalisation s’achever.

Les réglages sont verrouillés pendant une opération. Help reste accessible.

07 · Erreurs et arrêts

Un échec isolé ne doit pas nécessairement bloquer les autres fichiers. À l’inverse, une source ou une cible douteuse ne doit pas être considérée comme un dossier vide.

SituationRéaction de XtraSync
Fichier verrouillé ou erreur d’E/S transitoire isoléeDeux nouvelles tentatives, après 250 ms puis 750 ms. Si elles échouent, l’élément est journalisé en échec ; le travail indépendant continue.
Accès refusé, chemin invalide/trop long, dossier devenu non videÉchec de l’élément sans nouvelle tentative ; préservation des données restantes et poursuite du travail indépendant.
Fichier source disparu après l’aperçuÉchec de sa copie, préservation de sa destination existante. Cette disparition ne crée pas une nouvelle suppression de miroir.
Cible à supprimer déjà absenteSignalée comme déjà absente ; elle n’est pas comptée comme effectivement supprimée.
Balayage partiel ou impossiblePérimètre marqué Unavailable. Les modifications de ce périmètre et les changements destructeurs de ses parents sont bloqués ; il n’est jamais traité comme vide.
Échec d’une action préalableLes actions qui en dépendent sont ignorées : par exemple, pas de suppression du parent si un enfant n’a pas pu être supprimé.
Racine absente au démarrageArrêt avant modification des données. Les deux dossiers doivent être accessibles pour commencer.
Perte de source/cible ou erreur de connexion/périphérique indisponibleSuspension des écritures ; vérification toutes les deux secondes pendant un budget de 30 secondes. Arrêt si l’accès ne revient pas. Même s’il revient, un nouveau balayage et une nouvelle validation sont requis avant toute autre écriture.
Disque plein, stockage défectueux/protégé en écriture, CRC, corruption ou erreur grave de périphériqueArrêt immédiat et journalisation.
Ajout, changement de type, taille ou date imprévu ; violation de sécurité de chemin ; erreur inattendueArrêt. Corrigez la cause et repartez d’un plan neuf.

Limite globale d’erreurs de lecture

I/O read-error limit est un entier strictement positif, initialement 10 fichiers distincts par opération. Il compte les erreurs de lecture d’E/S non fatales, sur le contenu ou les métadonnées de fichiers connus, d’un côté ou de l’autre. Le même chemin absolu compte une seule fois, sans distinction de casse, même s’il échoue plusieurs fois ou pendant plusieurs phases.

Une lecture finalement réussie reste comptabilisée. Les succès intermédiaires et les changements de phase ne remettent pas le compteur à zéro. Dès que le seuil est atteint, l’opération s’arrête, avant une autre tentative sur ce fichier ou le traitement d’un fichier supplémentaire. La valeur utilisée et le compteur sont conservés dans le bilan ; une nouvelle opération repart à zéro.

Les fichiers manquants, permissions, verrouillages, chemins invalides et erreurs d’écriture gardent leur politique séparée et ne consomment pas ce seuil. Les erreurs graves de stockage et les pertes de connexion peuvent provoquer un arrêt plus tôt.

Comprendre le résultat final

  • Completed : travail terminé sans problème signalé ; une cible déjà absente ne constitue pas un échec.
  • Completed with warnings : par exemple erreur transitoire récupérée ou avertissement de configuration. Consultez le log.
  • Completed with issues : certains éléments ont échoué, ont été ignorés par dépendance, sont indisponibles ou en conflit. Consultez les compteurs et le log.
  • Stopped : arrêt demandé ou problème bloquant. Les actions restantes ne sont pas annoncées comme terminées.

Le délai de 30 secondes concerne la boucle de récupération entre les appels système. Windows peut bloquer un appel plus longtemps ; Pause, Stop et la fermeture de la fenêtre prennent alors effet lorsqu’il rend la main.

08 · Logs et rapports HTML

Un log par opération, un seul précédent

Chaque lancement de comparaison, miroir ou synchronisation crée XtraSync.log à côté de l’exécutable réellement lancé, y compris pour une opération annulée ou arrêtée. Au lancement suivant, l’ancien XtraSync.bak.log est supprimé et le log courant devient XtraSync.bak.log, avant la création du nouveau log. Il reste donc le log courant et, au plus, celui de l’opération précédente.

Le log contient les chemins, options et filtres, les phases, erreurs et avertissements avec leurs détails, puis un bilan final : durées, fichiers, dossiers, tailles prévues et réalisées, transferts partiels, remplacements, suppressions, conflits, échecs, nouvelles tentatives, récupérations et travail non traité. Copiez un log ailleurs avant d’enchaîner plusieurs nouvelles opérations si vous souhaitez le conserver.

Un verrou empêche deux instances utilisant le même dossier d’exécutable de faire tourner simultanément ces logs. Si le log ne peut pas être créé, l’opération ne commence pas. Un échec ultérieur d’écriture/finalisation est signalé à l’écran ; le bilan sur disque peut alors être incomplet.

Rapport HTML facultatif

Cochez Create HTML report after this run avant de lancer l’opération. Un rapport autonome est produit à la fin, y compris après un arrêt, une erreur ou un refus de l’aperçu lorsque la session de log a pu démarrer. Il contient le résultat, les diagnostics et les statistiques ; ce n’est pas une liste exhaustive de tous les fichiers parcourus. La case est remise à zéro après chaque opération : recochez-la pour le rapport suivant.

XtraSync-YYYY-MM-DD-HH-mm-ss.html
XtraSync-2026-11-18-14-32-09.html

Le nom reprend l’heure locale de début. Les deux-points sont remplacés par des tirets, compatibles avec Windows. En cas de collision à la même seconde, un suffixe -2, -3, etc. évite tout écrasement. Les rapports restent distincts, ne sont pas fusionnés et ne sont pas supprimés par la rotation des logs. Leurs chemins apparaissent en bas de la fenêtre ; ouvrez-les dans votre navigateur. Un échec de génération est signalé et journalisé si possible.

10 · Périmètre et protections

  • Application Windows autonome, pour deux chemins de dossiers accessibles par Windows. Les partages réseau restent soumis aux autorisations et à la disponibilité de la connexion.
  • Les racines identiques ou imbriquées sont refusées. Les liens symboliques, jonctions et autres points de réanalyse ne sont pas suivis ; leur détection provoque un arrêt de sécurité.
  • Les copies passent par un fichier temporaire voisin de la destination. La source et la cible sont revérifiées avant le remplacement final. Une conversion dossier vers fichier prépare d’abord la copie source avant de supprimer le sous-arbre cible.
  • Les actions approuvées ne sont pas élargies après validation. Un balayage incomplet ne justifie jamais de nouvelles suppressions.
  • Les logs, rapports et fichier d’aide générés à côté de l’exécutable sont ignorés par la synchronisation dans ce répertoire précis. Leurs dossiers parents sont protégés des suppressions destructrices. Les temporaires réservés .xtrasync-<32 caractères hexadécimaux>.tmp sont également ignorés ; un échec de nettoyage est signalé.

Pas de retour arrière global. Les copies terminées et suppressions validées restent effectives si une opération ultérieure échoue. La comparaison ne certifie pas l’intégrité du disque et XtraSync ne fournit pas d’historique de versions. Les contrôles ne peuvent pas empêcher toutes les modifications externes entre une vérification et un appel système.

11 · Résoudre un problème

QuestionÀ vérifier
Un fichier n’apparaît pasUn fichier jugé égal est compté dans le bilan et masqué dans le tableau. Vérifiez aussi Exclusions, les filtres de dossiers et Subfolders included. Une zone Unavailable peut masquer le contenu d’un dossier inaccessible. Les fichiers de sortie de XtraSync sont protégés dans son dossier de sortie.
Un fichier supprimé revient en bidirectionnelC’est le fonctionnement prévu : les fichiers présents d’un seul côté sont recopiés. Utilisez le miroir dans le bon sens si la source doit imposer ses suppressions.
Un fichier cible exclu reste présentPar défaut il est préservé. Pour le supprimer en miroir, cochez Delete excluded items from mirror destination et validez le nouveau plan. Cette option ne s’applique pas en bidirectionnel.
« Equal » mais contenu différentLa comparaison utilise taille/date, pas le contenu. Vérifiez vos critères et la tolérance ; l’option horaire peut aussi masquer un écart de dates.
La connexion est revenue mais l’opération s’est arrêtéeRelancez pour obtenir un état et un aperçu neufs. XtraSync ne reprend pas automatiquement un ancien plan après une perte de racine.

12 · Cette aide suit l’exécutable

Le bouton Help recrée XtraSync-help.html à côté de XtraSync.exe à partir de la documentation intégrée, à chaque clic, même si le fichier existe déjà et est identique, puis l’ouvre dans le navigateur par défaut. Les deux langues et tous les styles sont inclus dans ce seul fichier, sans téléchargement. Toute modification manuelle de la copie générée est remplacée au clic suivant.

Si l’écriture ou l’ouverture échoue, un message apparaît sous le titre de l’application, sans interrompre l’opération en cours. Si seule l’ouverture échoue, le fichier peut déjà avoir été recréé ; ouvrez-le manuellement. Si un onglet existant affiche encore une ancienne version, rechargez-le.

Si vous publiez depuis les sources, Publish.bat attend une touche à la fin pour vous laisser lire la console et renvoie le code de sortie de la publication.

User guide · English

Compare, understand,
synchronize.

A practical guide to comparing two folders, making a mirror and synchronizing both ways with XtraSync.

Button names match the English application interface. This guide works offline. Use the contents, Ctrl + F to search and Ctrl + P to print the displayed language.

A mirror can delete data. Check the direction and review the summary before applying changes. Deletions are permanent, bypassing the Recycle Bin, and XtraSync does not archive overwritten versions. Interrupting a run does not undo changes that have already completed.

01 · Getting started

  1. Run XtraSync.exe from a location you can write to: the application places its logs, reports and help there.
  2. Fill in LEFT FOLDER and RIGHT FOLDER by typing, using Browse…, or dragging a folder from File Explorer onto the field. Both folders must exist, be accessible and be separate. Nested folders are rejected.
  3. Choose your comparison criteria and exclusions. By default, subfolders, sizes and timestamps are included, with a two-second tolerance.
  4. Start with Compare folders to inspect differences. It does not change folder data, although it creates an operation log and an optional report.
  5. Choose a mirror direction or two-way synchronization. Review the exact actions, counts and sizes, then confirm with Apply mirror or Apply synchronization.
  6. Read the final result. If there are issues or warnings, check XtraSync.log; its path appears at the bottom of the window.

Drop one folder at a time. Its full path fills the field and is added to that side’s history. Files and multiple selections are ignored. The folder drop-downs separately retain the ten most recent left and right paths, without duplicates. Selecting a history entry does not start an operation.

02 · Choosing a mode

What the four main commands do
CommandBehavior
Compare foldersScans both sides and lists differences without copying or deleting folder data.
Mirror to right →Left is the source and right is the destination. Copies missing or different items from left to right; deletes destination items absent from the source within the selected scope.
← Mirror to leftRight is the source and left is the destination. The same rules apply in reverse.
Synchronize Both WayCopies items present on only one side to the other, and replaces an older version with a newer version when the rules can identify one. Deletions are never propagated.

In a mirror, the source is authoritative. When two files share a relative path and are within the mirror scope, either a timestamp difference detected by Compare timestamps after applying tolerance and the time-zone option, or a size difference detected by Compare sizes, is enough to schedule a replacement. An older source can overwrite a newer destination. If the enabled criteria return Equal, the destination file is kept.

A source file missing from the destination is scheduled for copying. A file/folder conflict may require deleting the destination item and recreating it using the source type. The review lists these actions.

Two-way synchronization does not remember deletions: deleting a file on one side while leaving it on the other causes it to be copied back. File/folder conflicts and differences without an identifiable newer version remain unchanged and appear in the preview. Resolve them manually, then run again.

03 · Comparison rules

XtraSync compares file metadata: size and modification timestamp. It does not calculate hashes or compare contents byte by byte. Files with the same size and timestamp can therefore be reported equal even when their contents differ.

OptionEffect
Subfolders includedOn by default. Includes subfolders and their contents. When off, only files directly in the roots are processed: subfolders and their contents are neither copied nor deleted.
Compare sizesOn by default. Different sizes indicate a difference when timestamps have not already identified a newer version.
Compare timestampsOn by default. Identifies the newer version and guides two-way copies.
Tolerance (seconds)A non-negative whole number, initially 2. Timestamp differences at or below the tolerance are equivalent. Timestamps are compared at whole-second precision.
Ignore whole-hour time zone differencesOff by default. Treats differences close to whole hours as equivalent within the chosen tolerance, for gaps under 24 hours. Use only when a time zone offset actually explains the difference.

If both criteria are off, two files at the same relative path are considered equal regardless of their contents. If timestamps are disabled or equivalent but sizes differ, two-way synchronization reports a conflict instead of choosing a version arbitrarily.

Reading the results table

The differences counter matches the number of rows in the table, both for a direct comparison and after a mirror or synchronization. Equal means the files match under the enabled criteria. Matching files and folders present on both sides are included in the comparison totals. An empty table after a completed comparison means zero differences within the scanned scope.

Paths are relative to the selected roots, and timestamps use local time. Left only / Right only indicates an entry present on one side, Left newer / Right newer a newer version on that side, Different size unequal sizes, Type conflict a file on one side and a folder on the other, and Unavailable insufficient access to reach a conclusion. Unavailable entries appear in the table and count toward differences.

04 · Exclusions and filters

Filtering happens upstream, during scanning. Excluded files are not opened for content reads or compared; excluded folders are not traversed. Their names and, when necessary, entry types are still inspected to apply the filter.

Entering the main exclusion line

Exclusions is an editable drop-down. Separate patterns with semicolons:

*.tmp; .git; file:*.bak; folder:bin; folder:obj; file:cache/*.log
  • A bare pattern matches files and folders.
  • file: restricts a pattern to files; folder: restricts it to folders.
  • The current line is saved automatically, including manual edits and clearing it. The ten most recent completed nonempty lines are retained without duplicates. Press Enter or leave the field to remember a complete line; reusing a line moves it to the top.

The Filters… dialog

The filter-icon button opens Name filters. On entry, the main line is split into Exclude files and folders, Exclude files and Exclude folders. Enter one pattern per line, without semicolons. Do not add file: / folder: prefixes inside the dedicated fields.

Save filters rebuilds and saves the main line with its separators and prefixes. Cancel discards dialog edits. Clear filters clears the draft; use Save filters afterwards to apply that change.

Pattern syntax

PatternMatches
*.tmpNames ending in .tmp, at any depth.
photo?.jpgExactly one character for ?, such as photo1.jpg.
folder:cacheEvery folder named cache, including all its contents.
file:cache/*.log.log files directly inside root-level cache; does not match other/cache/a.log or cache/sub/a.log.

* matches zero or more characters and ? one character, without crossing folder separators. A pattern without a separator matches a name at any depth; with / or \, it matches a path relative to the root. Matching ignores case. Leading/trailing spaces are trimmed; internal spaces and commas are literal. There is no include syntax, no ! exception and no special recursive meaning for **. Semicolons are reserved as pattern separators.

What happens to matching destination items?

Mirrors: excluded items are absent from the logical source. By default, matching destination items are preserved; their containing folders are protected against destructive deletion or type replacement.

The main-screen option Delete excluded items from mirror destination, initially off, allows their deletion in the mirror destination. Those deletions are included in the review. The destination changes with the selected mirror direction. To plan this cleanup, the destination must be inspected, including its excluded items; the source still uses upstream filtering.

Two-way synchronization: excluded items are simply ignored on both sides, without copying or deleting them. Excluded-item deletion is never applied in this mode, even when the option remains checked; a warning is logged in that case.

05 · Reviewing changes

Every mirror or synchronization builds a plan before modifying files. The confirmation dialog shows roots, direction, individual actions, folders to create/delete and conflicts left unchanged.

  • Files to copy (including replacements): file count and size of new versions to copy, including replacements.
  • Files to delete: count and size of files scheduled for explicit deletion.
  • Existing versions to overwrite (included above): count and size of old versions to overwrite. These files are already included in the copy group; do not add the groups as if they represented distinct files.

Totals describe operations: a type change may involve several actions on the same path. File sizes do not precisely predict required free space; preparing a copy uses a temporary file in the destination directory.

Apply mirror or Apply synchronization authorizes the displayed plan. Cancelling or closing the dialog does not change folder data. With no actions, nothing is executed. The plan is revalidated before execution; unexpected changes may require another scan and review.

The results table and the Review changes table use the same dark vertical and horizontal scrollbars.

06 · Progress and controls

The lower panel tracks scanning, comparison, planning, review and execution. Scanning has no known total yet, so the bar may be indeterminate. Execution percentage measures processed actions, rather than time remaining.

  • Copy / Delete: completed file counts and sizes against planned values; replacements are included in copies.
  • Folders: folders created and deleted, completed / planned.
  • Transferred: bytes transferred, including partial or repeated attempts; this can exceed the planned payload or committed bytes.
  • Current file: current path and within-file copy progress.
  • Problems: failed files/folders, skipped dependent work, already-absent items, unavailable entries, retries and distinct files with read errors.

Formatted sizes use units of 1,024 bytes.

Final comparison and disk activity

Compare folders after mirroring applies to either mirror direction. It is off by default and saved between sessions. When it is off, the table stays empty and the outcome shows Final comparison skipped. You can run Compare folders on demand. Both-way synchronization refreshes the table automatically after execution.

With the final comparison enabled, Scanning folders can appear after the copy and deletion counters reach their totals. XtraSync scans both folders again in read-only mode, displaying each path as it reads its metadata. The scanned volume adds up the sizes of the files found. Transferred still shows the bytes copied during execution. Comparing entries then uses the collected metadata to populate the differences table before the mirror outcome is displayed.

This comparison can reveal changes made during or after the mirror, for example by another program. Skipping it leaves any such differences to be checked manually. Plan revalidation, copy checks, the outcome and the log are part of execution in either case. The final check uses the selected size and timestamp criteria.

Background work and parallelism

Work runs in the background so the interface remains available. XtraSync scans the two folders in sequence, compares entries in memory one at a time and applies mirror actions in plan order. Files are copied one at a time, including in both-way synchronization.

Parallel scans could help on separate devices and slow down a shared hard drive. A parallel in-memory comparison, for example with PLINQ, would need to preserve result order and aggregate counters. Only independent mirror actions could overlap. A concurrency limit caps the number of active tasks. A bandwidth limit is a separate control, since one copy can saturate a slow drive.

ControlEffect
Pause / ResumePauses/resumes at the next checkpoint, including between copy blocks. An already-blocked Windows call can delay this.
StopRequests a clean stop, cleans temporary files where possible and finalizes the log and requested report. Completed actions remain in place.
RestartStops and waits for an active run if needed, then repeats the same mode with a fresh scan and plan. Changes require another confirmation. A new log is created.
Closing the windowRequests a stop and waits for finalization before exiting. Avoid force-closing the process if you want that finalization to finish.

Settings are locked during a run. Help remains available.

07 · Errors and stopping

An isolated failure need not block other files. An unreliable source or destination, however, must never be treated as an empty folder.

SituationXtraSync response
Locked file or isolated transient I/O failureTwo retries, after 250 ms and 750 ms. If they fail, records the item as failed and continues independent work.
Access denied, invalid/too-long path, directory that became nonemptyRecords an item failure without retrying, preserves remaining data and continues independent work.
Source file disappeared after previewFails its copy and preserves its existing destination. The disappearance does not create a new mirror deletion.
Deletion target is already absentRecords it as already absent; does not count it as an actual deletion.
Partial or failed scanMarks the scope Unavailable. Blocks changes within it and destructive changes to its ancestors; never treats it as empty.
A prerequisite action failedSkips dependent actions: for example, cannot remove a parent if a child deletion failed.
A root is missing at startupStops before changing folder data. Both roots must be accessible to begin.
Lost source/destination or transport/device-unavailable errorSuspends writes; checks every two seconds with a 30-second recovery budget. Stops if access stays unavailable. Even if access returns, requires a fresh scan and review before any further writes.
Disk full, faulty/write-protected storage, CRC, corruption or serious device I/O errorStops immediately and logs the failure.
Unexpected addition, type, size or timestamp change; unsafe path; unexpected errorStops. Correct the cause and start with a fresh plan.

Cumulative read-error limit

I/O read-error limit is a positive whole number, initially 10 distinct files per run. It counts nonfatal I/O read failures in file contents or known file metadata, on either side. The same absolute path counts once, ignoring case, even if it fails repeatedly or in several phases.

A read that eventually succeeds still counts. Successful intervening reads and phase changes never reset the counter. Reaching the limit stops the run before another attempt on that file or any additional file starts. The used limit and counter remain in the summary; a new run starts at zero.

Missing files, permissions, locks, invalid paths and write errors retain their separate policies and do not consume this budget. Serious storage faults and connection loss can stop the run earlier.

Understanding the final result

  • Completed: work finished without reported problems; an already-absent deletion target is not a failure.
  • Completed with warnings: for example, a recovered transient failure or configuration warning. Check the log.
  • Completed with issues: some items failed, were skipped by dependency, remained unavailable or conflicted. Check the counters and log.
  • Stopped: a requested stop or blocking failure interrupted the run. Remaining work is not reported as completed.

The 30-second budget applies to the recovery loop between system calls. Windows can block a call longer; Pause, Stop and window closing then take effect after it returns.

08 · Logs and HTML reports

One log per run, one previous log

Every comparison, mirror or synchronization attempt creates XtraSync.log beside the executable actually launched, including cancelled or stopped runs. At the next run, the old XtraSync.bak.log is deleted and the current log becomes XtraSync.bak.log, before creating the new current log. Only the current log and, at most, the previous run’s log remain.

The log records paths, settings and filters, phases, errors and warnings with details, then a final summary: duration, file and folder counts, planned and completed bytes, partial transfers, replacements, deletions, conflicts, failures, retries, recoveries and unprocessed work. Copy a log elsewhere before starting several more runs if you want to keep it.

A lock prevents instances sharing an executable directory from rotating these logs concurrently. If the log cannot be created, the operation does not start. A later write/finalization failure is reported on screen; the on-disk summary may then be incomplete.

Optional HTML report

Check Create HTML report after this run before starting. A self-contained report is produced at the end, including after a stop, failure or declined preview when a log session could start. It contains the outcome, diagnostics and statistics; it is not an exhaustive inventory of every scanned file. The checkbox resets after each run: select it again for the next report.

XtraSync-YYYY-MM-DD-HH-mm-ss.html
XtraSync-2026-11-18-14-32-09.html

The filename uses local start time. Hyphens replace colons for Windows compatibility. If two reports have the same second, suffixes such as -2, -3 prevent overwriting. Reports remain separate, are not merged and are not removed by log rotation. Their paths appear at the bottom of the window; open them in your browser. Report-generation failures are shown and logged where possible.

10 · Scope and protections

  • A self-contained Windows application for two folder paths accessible through Windows. Network shares remain subject to permissions and connection availability.
  • Identical or nested roots are rejected. Symbolic links, junctions and other reparse points are not followed; detecting them triggers a safety stop.
  • Copies use a temporary sibling of the destination. Source and destination are checked again before final replacement. Replacing a destination folder with a file prepares the source copy before deleting the target subtree.
  • The approved action list is never expanded after confirmation. An incomplete scan never authorizes new deletions.
  • Logs, reports and the generated help file beside the executable are ignored by synchronization in that specific directory. Their containing folders are protected from destructive deletion. Reserved .xtrasync-<32 hexadecimal characters>.tmp files are also ignored; cleanup failures are reported.

No global rollback. Completed copies and approved deletions remain in effect when a later action fails. Comparison does not certify disk integrity and XtraSync does not provide version history. Checks cannot prevent every external change between verification and a system call.

11 · Troubleshooting

QuestionCheck
A file is missing from the listA matching file is counted in the summary and hidden from the table. Also check Exclusions, folder filters and Subfolders included. An Unavailable scope can hide the contents of an inaccessible folder. XtraSync’s own output files are protected in its output directory.
A deleted file returns in two-way modeThis is expected: items on one side are copied to the other. Choose the appropriate mirror direction if the source must impose its deletions.
An excluded destination file remainsIt is preserved by default. To delete it in a mirror, select Delete excluded items from mirror destination and review the new plan. This option never applies in two-way mode.
“Equal” but different contentsComparison uses size/timestamp rather than content. Check your criteria and tolerance; the whole-hour option can also hide a timestamp difference.
Connection returned, but the run stoppedRun again for a fresh state and preview. XtraSync does not automatically resume an old plan after losing root access.
Read-error limit reachedRead the paths and exceptions in the log. Check storage and connection health before restarting. Successful intervening reads do not cancel cumulative failures.
Cannot create the log, report or helpCheck write permissions and free space beside the executable, locked files and other active instances. Move the application to a writable folder if needed.

12 · Help travels with the executable

The Help button recreates XtraSync-help.html beside XtraSync.exe from the embedded documentation on every click, even when the existing file is identical, then opens it in the default browser. Both languages and all styles are included in this single file, with no downloads. Manual edits to the generated copy are replaced on the next click.

If writing or opening fails, a message appears under the application title without interrupting the current operation. If only opening fails, the file may already have been recreated; open it manually. If an existing browser tab still shows an old version, reload it.

When publishing from the source tree, Publish.bat waits for a keypress so you can read the console and then returns the original publishing exit code.
